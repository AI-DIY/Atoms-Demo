## 实现思路与关键取舍

这次改造基于已有的 Next.js 工程。已有基础包括邮箱账户、Prisma/SQLite、角色注册表、Responses Provider、SSE 运行流和 HTML 版本。2.0 的重点是让这些能力形成可交付的完整产品流程，而不只是展示一次生成结果。

本轮进一步参考登录后的 Atoms 实际界面，增加首页、资源库和项目管理页，把原来的密集三栏调整为窄导航、团队对话和大面积编辑器。详细对照与实际截图见 [官网对照与改版说明](./官网对照与改版说明.md)。

### 1. 把智能体协作做成可观察的数据流

团队负责人负责交付计划，产品经理生成用户、范围、主流程和验收条件，架构师收敛页面与状态，工程师生成完整 HTML。各角色的输出通过 Zod 校验，以结构化产物传递给后续角色。SSE 及时发送步骤事件，运行、摘要和产物写入数据库；用户能展开团队交付文档查看具体内容。

这是同一模型的多角色编排，每个角色是独立模型请求。没有将一个固定回复伪装为多个真实 Agent，也没有宣称角色拥有未实现的联网研究或终端执行工具。`@研究员` 的结论来自模型与项目上下文，不能替代带来源的联网调研。

主流程自动执行“规划→构建→验收”，没有额外的人工审批步骤。工程师迭代时收到当前版本代码和修改要求，不从空白模板重新开始。失败保留已有应用和用户要求，重试继续原操作。

静态验收发现缺少需求标记时，会把缺失标准、已有代码和上游产物交回工程师，最多修复一次。动态列表功能的标记要求落在静态容器上，避免只能在运行后出现的标记被漏检。修复仍不合格就明确失败，不自动补写标记伪造通过，也不无限重试。这个机制检查需求覆盖声明，实际功能仍以浏览器操作为准。

### 2. 把复杂度控制在可以完整验证的边界

生成目标限定为单文件 HTML/CSS/JavaScript 应用。这样无需在线安装任意依赖、启动任意生成服务器或维护容器沙箱，仍能演示预约、内容计划、销售线索、计算器等交互式场景。前端与 API 使用同一个 Next.js 服务，SQLite 适合指定 2 核 / 2 GB 主机上的单实例交付。

代价是不能完整复刻 Atoms 的全栈云能力。需要复杂后端、外部 API、支付或文件系统的需求应明确收敛，不能暗示已经实现。

### 3. 隔离生成应用，同时支持业务数据持久化

生成代码始终运行在不含 `allow-same-origin` 的 iframe。清理生成 HTML 后，在它的脚本执行前注入 CSP：禁止网络连接、外部脚本、对象、表单外发和 base URL 改写。父页面不向 iframe 下发会话 Cookie、API Key 或 owner token。

为解决 opaque-origin iframe 无法直接使用真实 localStorage 的问题，宿主提供同名的小型存储 API。应用读写字符串快照；iframe 通过 `postMessage` 上报，父页面验证消息来源确实是当前 iframe，校验键、值类型及 64 KB 大小，然后通过已登录会话将快照写入项目数据库。数据格式不依赖具体业务模型，真实生成与模板共用此机制。

公开分享页面从空白访客存储开始，用独立的本地存储命名空间保存数据，不读取作者项目数据。HTML 下载只包含应用源码，不把宿主的桥接脚本、凭据或业务记录导出。

### 4. 分离工作版本、业务数据和发布版本

数据库同时保存当前工作版本和已发布版本。自然语言迭代生成新版本；恢复旧版本只切换工作版本，后续版本仍保留，业务数据不会回滚。发布将当前版本固定到不可预测的公开链接；再次发布更新同一个链接，取消发布让旧链接失效。

源码编辑也通过独立版本保存，复用 HTML 安全清理规则。接口验证登录身份、项目归属和 `baseVersion`，版本写入与恢复使用同一项目锁，防止过期编辑覆盖新成果。直接编辑代码不会隐式更新已公开的应用。

这使评审者可以在持续修改项目的同时体验稳定的已发布结果，也避免把版本回退误当成业务数据库回退。

### 5. 保持部署服务的边界

生产使用独立系统用户、独立目录、独立 systemd 服务与 Nginx 实例。Node 仅监听 `127.0.0.1:3000`，Demo 的 Nginx 仅监听 80。Dufs 的 Docker 容器、443 映射、数据、配置与证书不变。

构建进程限制 CPU 与内存；上线进程同样限制资源，数据库放在版本目录之外。激活脚本在切换前备份数据库、执行增量迁移，应用健康检查失败时尽可能切回旧版本。这个回退是应用版本回退，不能保证任意未来的破坏性数据库迁移都可自动回退。

### 已知限制

- 结构验收检查 JSON、大小、清理和 `data-acceptance` 标记覆盖，不等于确认业务逻辑正确。真实生成结果仍需要实际操作。
- 单实例 SQLite，进程内并发控制；不是面向大量并发用户的 SaaS。模型额度由所有账户共享，尚未实现每账户额度、收费或用量明细。
- 长任务尚未迁移到持久化队列。服务器重启可能中断运行，需要重新发起；完整的断点续跑、取消和跨进程互斥尚未实现。
- 存储桥支持 getItem/setItem/removeItem/clear/key/length，不提供完整浏览器 Storage 对象所有兼容行为。多标签页同时写入时采用最后写入，不做冲突合并。
- 每个项目列表最多返回最近 100 项；单份生成 HTML 不超过 50 KB，业务状态不超过 64 KB。
- 公开分享是前端应用展示，访客间不共享业务记录；下载 HTML 不包含工作区现有记录。
- 暂无邮箱验证、找回密码、文件上传、多人协作、GitHub 自动同步或自定义业务后端。
- Demo 使用 HTTP 80；现有 Dufs 占用 443。共享标准 HTTPS 入口需要独立规划，没有为本次 Demo 改造 Dufs 入口。

## AI Coding 工具使用说明

本次使用 **Codex 桌面应用** 辅助工程改造。实际工作包括：

1. 阅读本地笔试材料与既有工程，检索 Atoms 官方帮助文档；连接用户 Chrome，实际查看登录首页和已有聊天工作区，结合资源页截图整理差距。
2. 修改 TypeScript/React、API、Prisma 迁移、CSS 和部署脚本；不是把静态截图作为 Demo。
3. 执行已有测试，定位其环境与过时流程问题；补充持久化、发布、账户隔离和完整浏览器验收。
4. 通过 SSH 检查指定服务器、保存仅服务端模型配置、进行资源受限构建、部署与回归检查。
5. 编写中文 Markdown 交付文档，整理明确的完成度与限制，提交代码和版本标签。

产品运行时调用的是用户授权的 Responses 兼容服务及 `gpt-5.6-sol` 模型。它与开发阶段使用的 Codex 工具是两个不同用途。服务密钥只放在服务器的 `/etc/agent-studio.env`，仓库和文档没有该密钥。

用户表示已开通 Atoms Pro 70 美元会员。本轮使用其已登录 Chrome 查看官网首页与现有工作区，未购买或变更套餐，未在官网提交生成任务，因此不宣称消耗过官网生成额度。用户账单附件保留在本地材料中；实际订阅账单和本次 API 费用未经核实，不填写推测金额。

| 优先级 | 计划 | 优先的原因 |
| --- | --- | --- |
| P0 | 独立 HTTPS 入口、账户注册保护、用户额度和用量审计 | 在公开长期运行前控制账户与共享模型成本风险 |
| P0 | 持久化任务队列、心跳、断线重连、取消、重启恢复、项目锁 | 直接提高长任务可靠性和可预期性 |

| P1 | PostgreSQL、应用数据表模型、乐观并发控制 | 支持更大数据量、多实例与多用户一致性 |
| P1 | 运行成本和耗时可视化、版本差异、分支与备注 | 帮助用户判断修改价值和定位回归 |
| P1 | 独立生成应用域名、带权限的分享、访问审计 | 更强的隔离和可控协作 |
| P2 | 代码文件树、受限构建容器、按需组件与依赖 | 从单页原型扩展到多文件应用，投入与复杂度较高 |

优先保证生成可用、失败可恢复、数据可靠、成本可控，再扩大生成范围和外部集成数量。
